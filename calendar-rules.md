# Calendar Rules — PA (Personal Assistant)

Learning Adam's scheduling preferences. Each row maps an event pattern to a durable action.

## How This Works
- **Event Pattern**: A recognizable signature (e.g., title keyword, calendar, recurring cadence, time-of-day).
- **Action**: What PA should do when it matches (create / modify / delete / ignore / remind / ask).
- **Notes**: Context, exceptions, or Adam's rationale.

## Standing Rules
- NEVER create, modify, or delete a calendar event without Adam's explicit decision.
- First-time event patterns → ask Adam, then record the rule here.
- Read-only scans are always safe; mutations require approval.
